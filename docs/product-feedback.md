# Product feedback

## What worked well

The self-hosted MCP path makes a meaningful Alexa+ concept possible without preview access. MCP cleanly separates discovery and invocation, and JSON Schema makes tool arguments inspectable. Allowing a custom web MCP client gives judges a reproducible protocol-level demo.

## What was confusing

The minimum Streamable HTTP behavior must be composed from lifecycle, transport, and tools documentation. It would help to state directly whether POST-only JSON responses plus GET 405 are expected for bounded non-streaming hackathon tools. The relationship between the Alexa+ preview toolchain and the independent self-hosted MCP route initially requires careful FAQ reading.

## Improvements

Provide an official hackathon conformance command, a reference HTTP transcript, an automated submission checker, and a concise security checklist for consent-bearing tools. Clearly separate mandatory runtime hooks from optional Alexa+ preview integrations on every getting-started page.

## Would we build with it again?

Yes. A self-hosted MCP endpoint is portable and testable. We did not use or evaluate gated Category SDK, MCP Toolkit, CLI, or Alexa+ Web Simulator tooling.
